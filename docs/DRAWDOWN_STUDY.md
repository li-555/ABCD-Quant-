# 最大回撤诊断与现金预留配置

Volume 20% 的原筛选允许最大回撤最多增加 2 个百分点。2026 年 1–8 月收益从 10.55% 提高到 13.15%，最大回撤从 16.96% 增至 17.33%，所以当时通过了筛选。收益改善并不意味着每项风险指标都改善。

## 回撤为什么增加

原策略最大回撤发生于 2026-01-06 14:30 至 03-23 07:30 UTC；Volume 的最大回撤发生于 05-26 14:30 至 06-25 14:00 UTC。两者最大回撤不能当作完全相同区间的损益直接归因。

对齐到 Volume 的回撤区间后，原策略亏损 16.95%，Volume 亏损 17.33%。按各自在区间起点的净值归一化，SOL 额外拖累约 0.61 个百分点、WLD 约 0.34 个百分点，部分被 UNI、ETH 等改善抵消。Volume 该区间最大的绝对亏损来自 WLD、NEAR、SOL。全期平均总仓位原策略 33.45%、Volume 33.26%，因此证据指向持仓组成及进出时机变化，而非平均总仓位整体上升。

## 淘汰了哪些调整

在查看各候选结果之前固定 `research/drawdown_protocol.json`，比较降低 Volume 权重、降低总/单币仓位上限、降低波动目标、增强回撤缩仓、收紧止损等 8 个候选。要求在 2024、2025 年、正常与双倍成本四种情况下都满足：相对 Volume 最大回撤至少下降 1 个百分点、不超过原策略回撤、保留至少 85% 正收益、Sharpe 降幅不超过 0.1。

**没有候选全部通过，未采用这些参数调整。** 例如 2025 年把总仓位上限改成 60% 后，收益降至 16.52%、最大回撤反升至 26.13%；收紧止损也没有自动改善结果。原因是这些参数会改变交易路径，不能仅凭“更紧”推断更安全。

## 可选方案：固定预留初始资金的 15%

`bot/config/volume_cash85_research.yaml` 设置总初始权益 100,000、固定现金预留 15,000、策略初始资金 85,000。保持 Volume 20% 和原交易规则，策略按扣除预留后的权益计算目标仓位；预留金额不每日随净值调整，也不计利息。这是降低风险资金投入，不是新因子带来的超额收益。

以下各时期独立从 100,000 起算，扣单边 taker 10 bps 和滑点 2 bps；收益未年化。

| 时期 | 原策略收益 / 最大回撤 | Volume 收益 / 最大回撤 | Volume + 现金预留收益 / 最大回撤 |
|---|---:|---:|---:|
| 2024 | 57.80% / 19.76% | 54.28% / 17.32% | 46.14% / 15.33% |
| 2025 | 21.78% / 24.74% | 28.80% / 22.63% | 24.48% / 19.59% |
| 2026 年 1–8 月 | 10.55% / 16.96% | 13.15% / 17.33% | **11.18% / 15.05%** |
| 2026-09-01 至 09-29（28 天） | 23.15% / 6.16% | 22.59% / 6.44% | 19.20% / 5.55% |

双倍成本下，2026 年 1–8 月现金预留配置收益 1.97%、最大回撤 16.70%；原策略为 0.14%、20.94%，Volume 为 2.32%、19.38%。完整比较见研究结果 CSV。

现金预留情景在上述 8 项参数实验失败之后加入，没有搜索预留比例。**2024 至 2026 年 8 月已经被反复观察，这些结果属于回顾性诊断，不能再称为新的留出验证。** 9 月只覆盖 28 天，收益也低于原策略，不足以证明长期稳健。没有宣称现金预留配置通过前述参数筛选门槛。

## 接入及复现

先按 [因子研究](FACTOR_STUDY.md) 下载月度历史。9 月扩展来自 Binance 公共 REST K 线，固定截止于 2026-09-29 00:00 UTC；原月度档案在重叠区间优先。下载会检查覆盖率，研究脚本不静默填补缺口。

```bash
python -m research.download_factor_data --output cache/factor_history
python -m research.prepare_drawdown_data --output cache/drawdown_recent
python -m research.drawdown_study --output outputs/drawdown_study
python -m research.cash_reserve_study --output outputs/drawdown_study
python -m pytest tests -q
```

原研究使用的 9 月数据位于 `cache`；复跑原本地快照可向后两个命令传 `--recent-data cache`。数据文件 SHA256 记录在结果内，数据供应商后续修订可能导致重新下载结果有差异。现金预留研究先检查实际现金/数量账本与 `0.85 * Volume净值 + 15,000` 逐点一致，再输出指标，不只对最终指标做乘法。

设置环境变量 `LIVE=0` 后进行纸面运行：

```bash
python -m bot.main --config bot/config/volume_cash85_research.yaml --once
```

该配置使用独立日志和状态路径。原默认配置预留为 0，各新增因子默认权重为 0。切换配置需使用新状态和匹配的起始资金，不能直接复用旧峰值记录。日志同时记录总权益和策略权益。预留是策略资金核算规则，不是托管隔离，也不保证最大回撤永远低于 15%；它不能消除跳空、执行和交易所风险。未修改或启用任何真实交易账户。

历史回放复用信号、组合和止损函数，但不是整个实时 scheduler 的逐订单仿真；原 scheduler 累计峰值、同周期止损后账户刷新等差异仍见因子报告。现金預留配置先用于纸面验证。

## 检查

79 项离线测试通过，包含未来数据不影响历史信号、缓存更新、实际成本账本、现金预留的净值/订单数量缩放，以及 scheduler 使用 85,000 策略权益但报告 100,000 总权益的集成检查。6 条警告来自旧研究模块的 pandas 弃用用法。Windows 沙箱测试启动方式见因子报告。
